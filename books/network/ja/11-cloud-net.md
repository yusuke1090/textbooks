# 11. クラウドのネットワーク（VPC・サーバーレス）

クラウドの中にも、この本で見てきたものが全部あります。サブネット・ルーター・NAT・ファイアウォール・ロードバランサー・DNS・CDN です。ちがうのは、どれも機械を買わずに、画面や設定ファイルで作ることです。

## VPC: クラウドの中の、自分だけのネットワーク

**VPC**（Virtual Private Cloud）は、クラウドの中に作る、自分だけのプライベートなネットワークです。家の LAN をクラウドの中に作るようなものです。

![VPC の中のサブネットと、外とのつながり](images/vpc.svg)

| 部品 | 意味 | 家でいうと |
| --- | --- | --- |
| **VPC** | `10.0.0.0/16` のような、自分のプライベート IP アドレスの範囲 | 家の LAN 全体 |
| **サブネット** | VPC を AZ ごとに分けたもの（`10.0.1.0/24` など） | 部屋ごとの LAN |
| **インターネットゲートウェイ** | VPC とインターネットの出入り口 | 光回線の入り口 |
| **ルートテーブル** | サブネットごとの道の表（5章） | ルーターの設定 |
| **NAT ゲートウェイ** | 中から外へ出るときだけ通す NAT（7章） | 家のルーターの NAT |
| **セキュリティグループ** | サーバーごとのファイアウォール（8章） | 機械ごとの関所 |

### パブリックサブネットとプライベートサブネット

- **パブリックサブネット**: ルートテーブルに「その他は全部インターネットゲートウェイへ」がある。グローバル IP アドレスを付ければ、外から届く。ロードバランサーや、外から入る入り口のサーバーを置く
- **プライベートサブネット**: インターネットゲートウェイへの道がない。外から直接は届かない。アプリのサーバーやデータベースを置く。OS の更新などで外へ出るときは、NAT ゲートウェイを通る

大事なものほど奥に置き、入り口を1つにするのが基本です。

### セキュリティグループ

セキュリティグループは、サーバーごとに「どこから、どのポートを通すか」を決めます。中から出た通信の返事は自動で通ります（ステートフル）。

| 置く所 | 通すもの |
| --- | --- |
| ロードバランサー | どこからでも 443（HTTPS） |
| アプリのサーバー | ロードバランサーのセキュリティグループからだけ 8000 |
| データベース | アプリのサーバーのセキュリティグループからだけ 5432（PostgreSQL） |
| 管理用 | 自分の家や会社の IP アドレスからだけ 22（SSH） |

IP アドレスではなく「このグループから」と書けるので、サーバーの台数が変わっても決まりを直さずにすみます。SSH の 22番を「どこからでも（`0.0.0.0/0`）」にしないことが大事です。

### 会社ごとの呼び名

| 中身 | AWS | Google Cloud |
| --- | --- | --- |
| 自分のネットワーク | VPC | VPC ネットワーク |
| 仮想のサーバー | EC2 | Compute Engine |
| ファイアウォール | セキュリティグループ | ファイアウォールルール |
| ロードバランサー | ELB（ALB・NLB） | Cloud Load Balancing |
| DNS | Route 53 | Cloud DNS |
| CDN | CloudFront | Cloud CDN |
| 家や会社とつなぐ | Site-to-Site VPN・Direct Connect | Cloud VPN・Cloud Interconnect |

Azure では、VNet・Virtual Machines・ネットワークセキュリティグループ・Azure Load Balancer・Azure DNS・Azure Front Door・ExpressRoute などと呼びます。

## サーバーを1台立ててみる

どの会社でも、流れはほぼ同じです。

1. 東京のリージョンを選び、仮想のサーバーを作る。OS は Ubuntu 24.04、大きさは一番小さいもの（無料の枠があればそれ）
2. SSH の鍵を登録する（作った鍵か、その場で作ってダウンロード）
3. ファイアウォール（セキュリティグループ）で、22番は自分の IP アドレスからだけ、80番はどこからでも、を通す
4. 画面に出た外の IP アドレスに SSH でつなぐ

```bash
ssh -i ~/Downloads/mykey.pem ubuntu@203.0.113.10
```

5. Web サーバーを入れて、手元のブラウザで `http://203.0.113.10` を開く

```bash
sudo apt update && sudo apt install -y nginx
curl -I http://localhost     # HTTP/1.1 200 OK が返れば動いている
```

6. 試し終わったら、サーバーを**消す**（止めるだけでは、ディスクや IP アドレスの料金がかかることがある）

## サーバーレス: サーバーを持たない

**サーバーレス**は、サーバーそのものを用意せず、「この URL に来たらこの関数を動かす」「このデータが書きかわったらこの処理」のように、仕事の単位で頼む使い方です。サーバーがないのではなく、サーバーの面倒をクラウドの会社が全部みます。

- リクエストが来たときだけ動き、その回数と時間だけはらう。だれも使っていなければ、ほぼ0円
- アクセスが急に増えても、自動で増える
- しばらく使われていないと、最初の1回だけ起動に時間がかかる（**コールドスタート**）。1回に動ける時間にも上限がある

| 種類 | 例 |
| --- | --- |
| 関数を動かす（FaaS） | AWS Lambda・Google Cloud Run functions・Azure Functions |
| コンテナを動かす | Google Cloud Run・AWS Fargate（Docker のイメージをそのまま置ける） |
| 部品を使う（BaaS） | Firebase（ログイン・データベース・ファイル）・Supabase |
| 決まったファイルを配る | GitHub Pages・Cloudflare Pages・Amazon S3 ＋ CloudFront |

### 例: この教科書のサイト

この教科書のサイトは、自分で管理するサーバーを1台も持っていません。

| 仕事 | 使っているもの |
| --- | --- |
| HTML・章の Markdown・写真を配る | GitHub Pages（CDN から配られる） |
| ID とパスワードでのログイン | Firebase Authentication |
| 勉強の記録を、スマホと PC で合わせる | Firebase の Firestore（東京のリージョン） |
| 自分の記録だけを読み書きできるようにする | Firestore のセキュリティルール |

ブラウザが直接 Firebase と話し、だれがどのデータを読めるかはルールで決めています。使う人が少ないあいだは、無料の枠の中で動きます。

Docker のイメージを作れれば（[Docker の教科書](https://yusuke1090.github.io/textbooks/?b=docker)）、Cloud Run などに置いて、サーバーを持たずに動かすこともできます。

## まとめ

- VPC はクラウドの中の自分のネットワーク。AZ ごとのサブネット・ルートテーブル・インターネットゲートウェイ・NAT ゲートウェイで作る
- 入り口（ロードバランサー）はパブリックサブネット、アプリとデータベースはプライベートサブネット
- セキュリティグループで、サーバーごとに通すポートと相手を決める。SSH を世界中に開けない
- サーバーレスは、仕事の単位で頼み、使った分だけはらう。決まったファイルなら GitHub Pages などで配れる

## 練習問題

```quiz
Q: クラウドの中に作る、自分だけのプライベートなネットワークを何といいますか（アルファベット3文字）。
A: VPC | Virtual Private Cloud
E: Azure では VNet と呼びます。

Q: インターネットゲートウェイへの道がなく、外から直接届かないサブネットを何といいますか。
A: プライベートサブネット | private subnet | プライベート
E: アプリのサーバーやデータベースを置きます。

Q: プライベートサブネットのサーバーが、OS の更新などで外へ出るときに通るものは何ですか。
A: NAT ゲートウェイ | NATゲートウェイ | NAT gateway | NAT
E: 中から外へ出る通信だけを通します。

Q: AWS で、サーバーごとに通すポートと相手を決めるファイアウォールを何といいますか。
A: セキュリティグループ | security group | SG
E: ステートフルなので、中から出た通信の返事は自動で通ります。

Q: サーバーレスで、しばらく使われていない関数が最初の1回だけ起動に時間がかかることを何といいますか。
A: コールドスタート | cold start
E: よく使われている間は、すぐに動きます。
```
