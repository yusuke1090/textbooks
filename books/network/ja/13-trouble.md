# 13. つながらないときに調べる

「ネットがつながらない」「ラズパイの画面が PC から見えない」ときは、思いつきで設定をいじる前に、**下の階層から順に**確かめます。1章の階層を、下から1段ずつ上がっていくと、どこで止まっているかがわかります。

![絡まったケーブル](images/tangled-cables.jpg)

## 下から順に確かめる

| 段（確かめること） | コマンド |
| --- | --- |
| 1. 線・電波（ケーブルがささっている・Wi-Fi につながっている） | `ip -br link` |
| 2. IP アドレス（正しい IP アドレスをもらえている） | `ip -br addr` |
| 3. ゲートウェイ（家のルーターまで届く） | `ping -c 3 192.168.3.1` |
| 4. インターネット（外の IP アドレスまで届く） | `ping -c 3 8.8.8.8` |
| 5. DNS（名前を引ける） | `dig example.com` |
| 6. ポート（相手のポートが開いている） | `nc -zv example.com 443` |
| 7. アプリ（アプリが正しく答える） | `curl -v https://example.com/` |

### 1. 線・電波

```bash
ip -br link
```

```text
lo        UNKNOWN  00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP>
enp2s0    DOWN     dc:a6:32:12:34:57 <NO-CARRIER,BROADCAST,MULTICAST,UP>
wlp3s0    UP       dc:a6:32:12:34:56 <BROADCAST,MULTICAST,UP,LOWER_UP>
```

`NO-CARRIER` はケーブルの先が来ていない（ささっていない・相手の電源が切れている・ケーブルが切れている）という意味です。Wi-Fi の電波の強さは `nmcli dev wifi` の `SIGNAL`（0〜100）で見られます。

### 2. IP アドレス

```bash
ip -br addr
```

| 見えたもの | 意味 |
| --- | --- |
| `192.168.3.123/24` など | もらえている。次へ |
| `169.254.x.x` | DHCP の答えがなく、自分で付けた（5章）。ルーターが答えていない |
| 何もない | つながっていない（1に戻る）か、DHCP の設定が切れている |

### 3〜4. ゲートウェイとインターネット

ゲートウェイには届くのに `8.8.8.8` に届かないなら、家のルーターより外の問題です。ルーターや ONU のランプ、プロバイダの障害情報を見ます。どこで止まるかは `tracepath -n 8.8.8.8`（5章）でわかります。

### 5. DNS

`ping 8.8.8.8` は通るのに、`ping example.com` で `Temporary failure in name resolution` と出るなら DNS です。

```bash
dig example.com              # いつもの DNS サーバーに聞く
dig @1.1.1.1 example.com     # 別の DNS サーバーに聞いてみる
resolvectl status            # いま使っている DNS サーバー
```

別の DNS サーバーなら答えが返るなら、いつもの DNS サーバー（ルーターやプロバイダ）の問題です。

### 6〜7. ポートとアプリ

```bash
nc -zv example.com 443                 # succeeded! ならポートは開いている
curl -v https://example.com/ -o /dev/null
```

| 出たもの | 意味 |
| --- | --- |
| `Connection refused` | 相手には届いたが、そのポートで待っているアプリがない |
| 何も返らずに時間切れ | 途中のファイアウォールが捨てている。または相手まで届いていない |
| 証明書のエラー | 時計がずれている・名前がちがう・期限切れ（9章） |
| 4xx・5xx | 通信はできている。頼み方か、サーバーの中の問題（2章） |

## ラズパイや Jetson で動かしたサーバーが、PC から見えない

よくあるのは、サーバーが自分の中（`127.0.0.1`）だけで待っている場合です。ラズパイの上で `ss` で確かめます。

```bash
ss -tlnp      # 待っている TCP（l）を、プロセスの名前つきで（p）
```

```text
State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port  Process
LISTEN  0       128         127.0.0.1:5000        0.0.0.0:*     users:(("python3",pid=812,fd=3))
LISTEN  0       128           0.0.0.0:22          0.0.0.0:*     users:(("sshd",pid=401,fd=3))
```

- `127.0.0.1:5000` は、ラズパイの中からしかつなげない。外からも受けるには `0.0.0.0` で待つように起動する（Flask なら `flask run --host 0.0.0.0`、Python の簡易サーバーなら `python3 -m http.server 8000 --bind 0.0.0.0`）
- `0.0.0.0:22` は、どこからでも受ける。SSH はこうなっている

ほかに確かめること:

- ファイアウォールで止めていないか（`sudo ufw status`、8章）
- Docker のコンテナなら、`-p 5000:5000` でポートを出しているか（[Docker の教科書](https://yusuke1090.github.io/textbooks/?b=docker)）
- PC とラズパイが同じネットワークにいるか（`ip -br addr` のネットワーク部が同じか。お店の Wi-Fi やゲスト用の Wi-Fi は、機械どうしが話せない設定のことがある）

## パケットを直接見る: tcpdump と Wireshark

どうしてもわからないときは、流れているパケットそのものを見ます。

```bash
sudo tcpdump -n -i any port 53      # DNS の問い合わせと答えだけを見る
sudo tcpdump -n -i any host 192.168.3.50 and port 1883   # ラズパイとの MQTT
```

画面で見たいなら **Wireshark**（`sudo apt install wireshark`）が便利です。プロトコルごとに色分けされ、TCP の3ウェイハンドシェイク（4章）や TLS のあいさつ（9章）を、この本で見たとおりに1つずつ見られます。自分のネットワーク以外では使わないようにします。

## 遅いとき

| 確かめること | 方法 |
| --- | --- |
| 回線の速さ | ブラウザの速度テストのサイト。有線と Wi-Fi で比べる |
| LAN の中の速さ | 2台に `iperf3` を入れ、片方で `iperf3 -s`、もう片方で `iperf3 -c 相手の IP アドレス` |
| 遅延と、なくなるパケット | `mtr 8.8.8.8`（どのルーターから遅くなるか） |
| Wi-Fi の電波 | `nmcli dev wifi` の `SIGNAL`。ルーターに近づく・5 GHz にする |
| 夜だけ遅い | 日本の光回線なら PPPoE の混雑かもしれない。IPoE を確かめる（7章） |

## まとめ

- 線・電波 → IP アドレス → ゲートウェイ → インターネット → DNS → ポート → アプリ、と下から順に確かめる
- `169.254.x.x` は DHCP の失敗、`Temporary failure in name resolution` は DNS、`Connection refused` はポートで待つアプリがない
- 外から見えないサーバーは、`ss -tlnp` で `127.0.0.1` で待っていないかを見る
- どうしてもわからなければ、tcpdump や Wireshark でパケットそのものを見る

## 練習問題

```quiz
Q: `ip -br addr` で `169.254.` から始まるアドレスが出ました。どのしくみがうまくいっていませんか（アルファベット4文字）。
A: DHCP
E: ルーターからアドレスをもらえず、自分で付けたアドレスです。

Q: `ping 8.8.8.8` は通るのに、`ping example.com` が通りません。何を疑いますか（アルファベット3文字）。
A: DNS
E: IP アドレスまでは届いているので、名前を引くところが問題です。

Q: 相手には届いたが、そのポートで待っているアプリがないときに出るエラーは何ですか。
| nc -zv 192.168.3.50 5000
A: Connection refused | refused | 接続拒否
E: 何も返らずに時間切れになるなら、途中のファイアウォールが捨てていることが多いです。

Q: ラズパイの上で `ss -tlnp` をすると、サーバーが `127.0.0.1:5000` で待っていました。外からも受けるには、どのアドレスで待つように起動しますか。
A: 0.0.0.0
E: `0.0.0.0` は「全部のネットワークから受ける」の意味です。

Q: 流れているパケットをコマンドで見る道具は何ですか。
A: tcpdump | Wireshark | tshark
E: 画面で見るなら Wireshark が便利です。
```
