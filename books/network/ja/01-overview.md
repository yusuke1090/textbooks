# 1. ネットワークとは（URL を開いてからページが出るまで）

スマホで URL を押すと、1秒もたたずにページが出ます。そのあいだに、データは家の Wi-Fi・光ファイバー・プロバイダ・海底ケーブル・データセンターを通って、行って帰ってきています。この本では、その道のりを1つずつたどって「ネットワークはなぜつながるのか」を見ていき、最後にクラウドと IoT につなげます。

## ネットワークとインターネット

**ネットワーク**は、コンピューターどうしをつないで、データをやりとりできるようにしたものです。家の中の Wi-Fi も、会社の中の LAN も、1つのネットワークです。

**インターネット**は、世界中のネットワークどうしを、さらにつないだものです（inter = 〜のあいだ）。1つの会社が持っているのではなく、何万ものプロバイダ・会社・大学のネットワークが、同じ約束ごと（**プロトコル**）を守ってつながっています。

| 言葉 | 意味 | 例 |
| --- | --- | --- |
| **LAN** | 家や会社の中の、せまい範囲のネットワーク | 家の Wi-Fi、オフィスの有線 LAN |
| **WAN** | 遠くの場所どうしをつなぐ、広い範囲のネットワーク | 光回線、携帯電話の回線 |
| **インターネット** | 世界中のネットワークをつないだネットワーク | Web・メール・動画・クラウド |
| **プロトコル** | つなぐための約束ごと | HTTP・TCP・IP・Wi-Fi |

## URL を開いてからページが出るまで

`https://example.com/` を開いたときの流れを、ざっと見ます。2章から9章で、1つずつくわしく見ていきます。

![URL を開いてからページが出るまで](images/journey.svg)

1. **ブラウザ**が URL を読み、サーバーに送る「ください」というお願い（**HTTP のリクエスト**）を作る（2章）
2. `example.com` という名前を、**DNS** に聞いて **IP アドレス**（`104.20.23.154` のような番号）に変える（3章）
3. **TCP** でサーバーと「つなぐ」準備をして、データを小分けにした**パケット**に番号を付ける（4章）
4. パケットに、あて先の IP アドレスを書く。**ルーター**がバケツリレーのように次のルーターへ渡していく（5章）
5. 家の中は **Wi-Fi** や **LAN ケーブル**で、まず家のルーターまで届く（6章）
6. 家のルーターから光回線で**プロバイダ**へ。プロバイダどうしがつながる所や**海底ケーブル**を通って、サーバーのあるデータセンターへ（7章）
7. サーバーの前の**ファイアウォール**や**ロードバランサー**を通って、Web サーバーが答え（**レスポンス**）を返す。近くの **CDN** が代わりに答えることも多い（8章）
8. 途中で中身を盗み見られないよう、**HTTPS** で暗号にしてやりとりする（9章）

答えは同じ道を逆にたどって戻り、ブラウザが HTML を読んでページを描きます。ページの中の画像や CSS も、同じようにそれぞれ取りに行きます。

## パケット: データを小分けにして送る

ネットワークでは、大きなデータを、そのまま1本の線を占領して送るのではなく、1,500バイトくらいまでの小さな**パケット**に分けて送ります。

- 1本の線を、たくさんの人のパケットが順番に使える（電話のように線を占領しない）
- 途中で1つなくなっても、そのパケットだけ送り直せばよい
- パケットごとに、そのとき空いている道を通れる

パケットは、荷物に送り状を付けた宅配便のようなものです。中身（データ）の前に、あて先や番号を書いた**ヘッダー**が付いています。

## 階層（レイヤー）: 役割を分ける

ネットワークの仕事は、役割ごとの**階層**（**レイヤー**）に分かれています。上の階層は、下の階層がどう運ぶかを気にしなくてよい、というのがポイントです。Wi-Fi が有線 LAN に変わっても、ブラウザは何も変えずに動きます。

![階層ごとにヘッダーを付けて送る](images/layers.svg)

| 階層（TCP/IP） | 役割（宅配便でいうと） | 主なプロトコル |
| --- | --- | --- |
| アプリケーション層 | アプリどうしの会話の決まり（手紙の中身と書き方） | HTTP・DNS・SSH・MQTT（2・3・9・12章） |
| トランスポート層 | どのアプリに渡すか（ポート）、確実に届ける（受け取る人の名前、届いたかの確認） | TCP・UDP（4章） |
| インターネット層 | どのコンピューターへ、どの道で（住所と、配送センターの中継） | IP（5章） |
| リンク層 | となりの機械まで、電気や電波で運ぶ（トラックや自転車） | イーサネット・Wi-Fi（6章） |

送るときは、上の階層から順に**ヘッダーを付けて包み**（**カプセル化**）、受け取る側は下から順に**はがして**いきます。

教科書や試験では、7つに分けた **OSI 参照モデル**もよく出ます。TCP/IP の4つとの対応は次のとおりです。「L2 スイッチ」「L7 のロードバランサー」のように、番号で呼ぶことがあります。

| OSI 参照モデル | TCP/IP |
| --- | --- |
| 7 アプリケーション層・6 プレゼンテーション層・5 セッション層 | アプリケーション層 |
| 4 トランスポート層 | トランスポート層 |
| 3 ネットワーク層 | インターネット層 |
| 2 データリンク層・1 物理層 | リンク層 |

## インターネットのはじまり

![ARPANET のノードだった IMP（1969年）](images/arpanet-imp.jpg)

| 年 | できごと |
| --- | --- |
| 1969 | アメリカの **ARPANET** が4つの大学・研究所をつないで動きはじめる。インターネットの祖先 |
| 1983 | ARPANET が **TCP/IP** に切り替わる。いまのインターネットの約束ごとのはじまり |
| 1984 | 日本の大学をつなぐ JUNET ができる |
| 1989〜1991 | ヨーロッパの研究所 CERN で、ティム・バーナーズ＝リーが **World Wide Web**（URL・HTML・HTTP）を作る |
| 1990年代 | プロバイダが一般の人向けにインターネットを売りはじめる。日本では 1995年ごろから広まる |
| 2000年代 | ADSL・光回線で常時接続に。2007年ごろからスマホ。2006年に AWS のクラウドがはじまる（10章） |

Web は、インターネットの上で動く使い道の1つです。メール・動画・ゲーム・IoT のセンサーも、同じインターネットを使います。

## まとめ

- インターネットは、世界中のネットワークを、同じプロトコルでつないだもの
- データはパケットに分けて送り、ルーターがバケツリレーで運ぶ
- 役割は階層に分かれている（アプリケーション・トランスポート・インターネット・リンク）。送るときはヘッダーを付けて包み、受け取る側ではがす

## 練習問題

```quiz
Q: データを小分けにして、あて先などを書いたヘッダーを付けたものを何といいますか。
A: パケット | packet
E: 1,500バイトくらいまでのパケットに分けて送ります。なくなったパケットだけ送り直せます。

Q: ネットワークどうしが、同じ約束ごとを守ってつながるための、その約束ごとを何といいますか。
A: プロトコル | protocol | 通信プロトコル
E: HTTP・TCP・IP・Wi-Fi などがプロトコルです。

Q: TCP/IP の4つの階層で、IP アドレスとルーターを受け持つのは何層ですか。
A: インターネット層 | インターネット | internet layer | internet
E: OSI 参照モデルでは3層（ネットワーク層）にあたります。

Q: 送るときに、上の階層から順にヘッダーを付けて包むことを何といいますか。
A: カプセル化 | encapsulation
E: 受け取る側では、下の階層から順にヘッダーをはがしていきます。

Q: インターネットの祖先で、1969年にアメリカで動きはじめたネットワークの名前は何ですか。
A: ARPANET | アーパネット
E: 1983年に TCP/IP に切り替わりました。
```
