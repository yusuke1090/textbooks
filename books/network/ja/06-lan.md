# 6. LAN（イーサネットと Wi-Fi）

IP アドレスで「どこへ」が決まっても、実際に電気や電波で運ぶのは、となりの機械までです。家や会社の中の **LAN** で、パケットをとなりへ運ぶしくみが、有線の**イーサネット**と、無線の **Wi-Fi** です。

## イーサネット（有線 LAN）

![LAN ケーブルと RJ45 のコネクター](images/lan-cable.jpg)

**イーサネット**は、LAN ケーブルでつなぐ有線の LAN です。先の四角いコネクターを **RJ45** といいます。ケーブルは1本 100m までで、種類（カテゴリー）で出せる速さが決まります。

| カテゴリー | 速さ | 使い道 |
| --- | --- | --- |
| Cat5e | 1 Gbps | ふつうの家ならこれで足りる |
| Cat6 | 1 Gbps（短ければ 10 Gbps） | 少し余裕を見るなら |
| Cat6A | 10 Gbps | 10 Gbps の光回線やサーバー |

LAN ケーブルで電気も送る **PoE**（Power over Ethernet）を使うと、牛舎のカメラや天井の Wi-Fi の機械に、コンセントなしで電気を届けられます。

## MAC アドレス: となりの機械の名前

LAN の中で機械を見分けるのは **MAC アドレス**です。48ビットの数で、`dc:a6:32:12:34:56` のように 16進数で書きます。ネットワークの部品（LAN の口や Wi-Fi の部品）ごとに、工場で付けられています。

- 前の半分（`dc:a6:32`）は作った会社の番号。`dc:a6:32` はラズパイの会社
- IP アドレスは場所で変わるが、MAC アドレスは部品について回る
- iPhone や Android は、Wi-Fi ごとにでたらめな MAC アドレスを使う（「プライベート Wi-Fi アドレス」）。どこにいたかを追われないため

### フレーム

イーサネットで送る1つのまとまりを**フレーム**といいます。IP のパケットを、MAC アドレスのヘッダーで包んだものです。

```text
| あて先 MAC | 送り元 MAC | 種類（IPv4 など） | データ（IP のパケット、1,500 バイトまで） | 誤りチェック |
```

1回に入れられるデータの大きさ（1,500 バイト）を **MTU** といいます。

## スイッチ: 必要な口にだけ送る

![スイッチと ARP](images/lan.svg)

**スイッチ**（スイッチングハブ）は、LAN ケーブルを何本もつなぐ箱です。フレームが届くたびに「この MAC アドレスは何番の口にいる」と覚え（**MAC アドレステーブル**）、次からはその口にだけ送ります。ほかの機械の邪魔をしません。

![ラズパイとスイッチ](images/pi-switch.jpg)

まだ覚えていないあて先と、全員あて（**ブロードキャスト**、`ff:ff:ff:ff:ff:ff`）は、全部の口に送ります。

## ARP: IP アドレスから MAC アドレスを調べる

パソコンが `192.168.3.1`（ルーター）にパケットを送りたくても、フレームには MAC アドレスが必要です。そこで **ARP** で調べます。

1. パソコンが LAN の全員に「`192.168.3.1` の人、MAC アドレスを教えて」とブロードキャストする
2. ルーターだけが「私です。`18:2c:a9:00:00:01` です」と答える
3. パソコンは答えをしばらく覚えておく（ARP テーブル）

```bash
ip neigh      # 覚えている ARP テーブル
```

```text
192.168.3.1 dev wlp3s0 lladdr 18:2c:a9:00:00:01 REACHABLE
```

### IP アドレスは変わらず、MAC アドレスは毎回変わる

インターネットのサーバーへ送るとき、パソコンはフレームのあて先を**ルーターの MAC アドレス**にし、中の IP パケットのあて先は**サーバーの IP アドレス**のままにします。ルーターはフレームをはがし、次のルーターの MAC アドレスで包み直して送ります。

| | 最後まで同じ | となりへ渡すたびに変わる |
| --- | --- | --- |
| 何を決めるか | 最後のあて先（IP アドレス） | 次に渡す相手（MAC アドレス） |
| たとえ | 送り状の住所 | 配送センターから次の配送センターへのトラック |

## Wi-Fi（無線 LAN）

**Wi-Fi** は、電波でつなぐ LAN です。電波を出す親機を**アクセスポイント**、ネットワークの名前を **SSID** といいます。

| 電波の帯 | とどく範囲 | 速さ | 特ちょう |
| --- | --- | --- | --- |
| 2.4 GHz | 広い。壁を通りやすい | おそい | 電子レンジや Bluetooth と混ざりやすい。ピコ W など IoT の機械の多くは、これしか使えない |
| 5 GHz | ふつう | 速い | 混みにくい |
| 6 GHz | せまい | とても速い | Wi-Fi 6E・Wi-Fi 7 で使える。いちばん空いている |

| 呼び名 | 規格 | 年 |
| --- | --- | --- |
| Wi-Fi 4 | IEEE 802.11n | 2009 |
| Wi-Fi 5 | IEEE 802.11ac | 2013 |
| Wi-Fi 6 / 6E | IEEE 802.11ax | 2019 / 2020 |
| Wi-Fi 7 | IEEE 802.11be | 2024 |

- 電波は1つを順番に使う。だれかが送っている間は待つ（**CSMA/CA**）。つなぐ台数が多いと、1台あたりは遅くなる
- 中身は **WPA2** か **WPA3** で暗号にする（WEP は破られているので使わない）
- 家が広いときは、何台かの親機で1つの Wi-Fi を作る**メッシュ Wi-Fi** が便利。牛舎まで届かせるなら、屋外用のアクセスポイントや LAN ケーブルを引くほうが安定する

![屋外用の Wi-Fi のアクセスポイント](images/outdoor-ap.jpg)

## 家のルーターは、いくつもの機械が1つになったもの

![家のルーター（ホームゲートウェイ）](images/home-router.jpg)

家の「Wi-Fi ルーター」1台の中には、この本で出てくる機械が全部入っています。

| 中身 | 仕事 | 章 |
| --- | --- | --- |
| ルーター | 家の LAN と、インターネットの間でパケットを渡す | 5 |
| スイッチ | 後ろの LAN の口どうしをつなぐ | 6 |
| Wi-Fi のアクセスポイント | 電波でつなぐ | 6 |
| DHCP サーバー | つないだ機械に IP アドレスを配る | 7 |
| NAT | プライベート IP アドレスを、1つのグローバル IP アドレスにまとめる | 7 |
| DNS の中継 | 名前の問い合わせを、プロバイダの DNS サーバーへ取り次ぐ | 3 |
| ファイアウォール | 外から勝手に入ってくる通信を止める | 8 |

## まとめ

- LAN の中で機械を見分けるのは MAC アドレス（48ビット、部品ごと）
- スイッチは MAC アドレスを覚えて、必要な口にだけフレームを送る
- ARP で、IP アドレスから MAC アドレスを調べる
- 最後のあて先（IP アドレス）は変わらず、となりへ渡す相手（MAC アドレス）は毎回変わる
- Wi-Fi は 2.4 GHz（遠くまで、IoT 向き）・5 GHz・6 GHz（速い）を使い分ける

## 練習問題

```quiz
Q: LAN の中で機械を見分ける、48ビットのアドレスを何といいますか。
A: MAC アドレス | MAC | MACアドレス | MAC address
E: 前の半分は、作った会社の番号です。

Q: IP アドレスから MAC アドレスを調べるプロトコルは何ですか。
A: ARP
E: 「この IP アドレスの人は?」と全員に聞き、本人が答えます。

Q: MAC アドレスを覚えて、必要な口にだけフレームを送る機械を何といいますか。
A: スイッチ | スイッチングハブ | switch | L2 スイッチ
E: 覚えていないあて先とブロードキャストは、全部の口に送ります。

Q: イーサネットで、1回のフレームに入れられるデータの大きさ（ふつう 1,500 バイト）を何といいますか。
A: MTU
E: Maximum Transmission Unit の略です。

Q: ピコ W など IoT の機械の多くが使える、Wi-Fi の電波の帯は何 GHz ですか。
A: 2.4 | 2.4GHz
E: 2.4 GHz は遠くまで届き、壁も通りやすいですが、混みやすいです。
```
