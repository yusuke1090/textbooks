# 8. サーバーの側（ファイアウォール・ロードバランサー・CDN）

パケットは海をわたって、サーバーのあるデータセンターに着きました。大きなサイトでは、1台のサーバーが全部に答えているわけではありません。入り口で守り、たくさんのサーバーに仕事を分け、ときには利用者の近くで代わりに答えます。

## データセンター

![データセンターのサーバーのラック](images/server-racks.jpg)

**データセンター**は、サーバーを何千台も置くための建物です。止まらないように、電気・冷やす機械・回線を二重にしています。サーバーは、19インチの**ラック**という棚に積んで並べます。

## ファイアウォール: 入ってよい通信だけ通す

**ファイアウォール**は、決まりに合う通信だけを通し、ほかは止める関所です。

- 「どこから・どこへ・どのポートへ」で決める。例: 「外からは 443番（HTTPS）だけ通す。22番（SSH）は会社の IP アドレスからだけ」
- 中から出ていった通信の返事は、覚えておいて通す（**ステートフル**）
- 家のルーター・会社の入り口・サーバーの OS・クラウドのセキュリティグループ（11章）など、何か所にも置く

Ubuntu では `ufw` で設定できます。ラズパイや Jetson を外から見える所に置くときにも使います。

```bash
sudo ufw default deny incoming   # 外からは、基本は全部止める
sudo ufw allow 22/tcp            # SSH は通す
sudo ufw allow 443/tcp           # HTTPS は通す
sudo ufw enable
sudo ufw status
```

SSH でつないでいる機械で、22番を通す前に `ufw enable` すると、自分も入れなくなります。順番に注意します。

## ロードバランサー: 仕事を分ける

**ロードバランサー**は、たくさんのリクエストを、後ろの何台ものサーバーに分けて渡す機械（またはソフト）です。

- 1台のサーバーでは足りないとき、台数を増やして全体の力を上げられる（**スケールアウト**）
- 1台がこわれても、ロードバランサーが気づいて（**ヘルスチェック**）、残りのサーバーにだけ渡す
- サーバーを1台ずつ止めて更新すれば、サイトを止めずに入れかえられる

| 種類 | 見るもの | できること |
| --- | --- | --- |
| L4（トランスポート層） | IP アドレスとポート | 速い。中身は見ない |
| L7（アプリケーション層） | URL・ヘッダー・Cookie | `/api/` は API のサーバーへ、`/images/` は画像のサーバーへ、のように分けられる。HTTPS の暗号をここでほどくことが多い |

## Web サーバーとアプリのサーバー

ロードバランサーの後ろでは、役割の分かれたソフトが動いています。

| ソフト | 仕事 | 例 |
| --- | --- | --- |
| **Web サーバー** | HTML・画像などのファイルを返す。後ろのアプリに取り次ぐ | nginx・Apache・Caddy |
| **アプリのサーバー** | ログイン・検索・注文など、そのつど計算して答えを作る | Python（Django・FastAPI）・Node.js・Go など |
| **データベース** | データをしまい、探す | PostgreSQL・MySQL・Redis |

データベースは外から直接つなげない、奥のネットワークに置きます（11章）。

## CDN: 近くで代わりに答える

![CDN は利用者の近くのサーバーから返す](images/cdn.svg)

7章で見たように、遠いサーバーとのやりとりは光の速さでも時間がかかります。そこで、世界中の何百か所にサーバー（**エッジ**）を置き、画像や HTML の写しを取っておいて、利用者に一番近いエッジから返すのが **CDN**（Content Delivery Network）です。

- 元のサーバー（**オリジン**）まで行かないので速い。オリジンの負担も減る
- 写しを持っていなかったり古くなったりしたときだけ、オリジンに取りに行く
- 大量のアクセスで攻撃されても（DDoS）、世界中のエッジで受け止められる
- 代表的な会社は Cloudflare・Akamai・Fastly・Amazon CloudFront。この教科書のサイト（GitHub Pages）も CDN から配られている

2章の `example.com` のヘッダーにも、CDN の様子が出ていました。

```text
Server: cloudflare
Age: 13682
cf-cache-status: HIT
CF-RAY: a5c6c32e5a87e052-KIX
```

`cf-cache-status: HIT` は「エッジに写しがあったので、それを返した」、`Age` は写しを取ってからの秒数、`CF-RAY` の最後の `KIX` は、答えたエッジが関西（関西空港の記号）にあることを表しています。

## エニーキャスト: 同じ住所が世界中にある

`8.8.8.8`（Google の DNS）や `1.1.1.1`（Cloudflare の DNS）、DNS のルートサーバーは、同じ IP アドレスを世界中の何百か所で使っています（**エニーキャスト**）。それぞれの場所が BGP（7章）で「このアドレスはうちに来て」と知らせるので、パケットはルーターの道の選び方で、一番近い所に自然に届きます。CDN も、この方法でエッジを選ぶことが多いです。

## まとめ

- データセンターでは、電気・冷やす機械・回線を二重にして、サーバーをラックに積む
- ファイアウォールで必要なポートだけを通す。Ubuntu では `ufw`
- ロードバランサーが何台ものサーバーに仕事を分け、こわれたサーバーをよける
- CDN は、利用者に近いエッジから写しを返して、速く・強くする
- エニーキャストで、同じ IP アドレスを世界中の近い所が受ける

## 練習問題

```quiz
Q: 決まりに合う通信だけを通し、ほかを止める仕組みを何といいますか。
A: ファイアウォール | firewall | FW
E: 「どこから・どこへ・どのポートへ」で決めます。

Q: たくさんのリクエストを、後ろの何台ものサーバーに分けて渡すものを何といいますか。
A: ロードバランサー | ロードバランサ | load balancer | LB
E: こわれたサーバーをヘルスチェックで見つけて、よけることもします。

Q: 利用者の近くのサーバーに写しを置いて、速く返すしくみを何といいますか（アルファベット3文字）。
A: CDN | Content Delivery Network
E: Cloudflare・Akamai・Fastly・Amazon CloudFront などがあります。

Q: 同じ IP アドレスを世界中の何か所でも使い、一番近い所に届くようにする方法を何といいますか。
A: エニーキャスト | anycast
E: 8.8.8.8 や 1.1.1.1、DNS のルートサーバーで使われています。

Q: Ubuntu でファイアウォールを設定するコマンドは何ですか。
A: ufw | ufw コマンド
E: `sudo ufw allow 22/tcp` のように、通すポートを決めます。
```
