# 10. クラウドとは

ここまでで、ネットワークの先にはデータセンターのサーバーがあることを見てきました。**クラウド**は、そのデータセンターのコンピューターを、インターネット越しに、使った分だけ借りるしくみです。

## 自分で持つか、借りるか

昔は、サービスを始めるにはサーバーを買い、置き場所と回線を用意し、こわれたら自分で直していました（**オンプレミス**）。クラウドでは、画面やコマンドで頼むと数十秒でサーバーができ、いらなくなったら消せます。

電気にたとえると、オンプレミスは自分の発電機、クラウドは電力会社の電気です。

| | オンプレミス | クラウド |
| --- | --- | --- |
| 始めるとき | サーバーを買う。数週間かかる | 数分。最初のお金はほぼいらない |
| はらうお金 | 買ったときに大きく | 使った分だけ（秒・時間・GB ごと） |
| 増やす・減らす | 買い足す。減らせない | すぐ増やせて、すぐ減らせる |
| こわれたとき | 自分で直す | 機械の故障はクラウドの会社が直す |
| 気をつけること | 置き場所・電気・回線 | 使いすぎの料金・その会社への依存 |

アメリカの国立標準技術研究所（NIST）は、クラウドの特ちょうを「自分で頼める・ネットワークから使える・たくさんの人で共有する・すぐ増やせる・使った分をはかる」の5つにまとめています。

## IaaS・PaaS・SaaS: どこまで借りるか

![どこまでを自分で、どこからをクラウドの会社が受け持つか](images/cloud-models.svg)

| 形 | 借りるもの | 自分ですること | 例 |
| --- | --- | --- | --- |
| **IaaS** | 仮想のサーバー・ディスク・ネットワーク | OS から上は全部 | Amazon EC2・Google Compute Engine・Azure Virtual Machines |
| **PaaS** | アプリを動かす場所 | 自分のアプリのコードとデータ | Google Cloud Run・App Engine・Azure App Service・Heroku |
| **サーバーレス**（FaaS・BaaS） | 関数を動かす場所、ログインやデータベースなどの部品 | 関数のコード・設定 | AWS Lambda・Cloud Functions・Firebase |
| **SaaS** | できあがったアプリ | 使うだけ | Gmail・Google ドキュメント・Microsoft 365・GitHub |

上に行くほど楽ですが、自由は少なくなります。ラズパイと同じように Ubuntu を入れて好きに使いたいなら IaaS、作ったアプリを置くだけなら PaaS やサーバーレスが向いています。

## クラウドの会社

| 会社 | 始まり | 特ちょう |
| --- | --- | --- |
| **AWS**（Amazon Web Services） | 2006年（S3・EC2） | 一番大きく、サービスの数が多い |
| **Microsoft Azure** | 2010年 | Windows・Office・会社のシステムとつなぎやすい。OpenAI の AI を使える |
| **Google Cloud** | 2008年（App Engine） | データ分析と AI、Firebase |

この3社で、世界のクラウドの6割ほどを占めています。日本にも、さくらインターネット・IIJ・NTT などのクラウドがあります。

## リージョンとアベイラビリティゾーン

クラウドの会社は、世界の各地にデータセンターのまとまり（**リージョン**）を持っています。日本には東京と大阪のリージョンがあります。

| | AWS | Google Cloud |
| --- | --- | --- |
| 東京 | `ap-northeast-1` | `asia-northeast1` |
| 大阪 | `ap-northeast-3` | `asia-northeast2` |

- 使う人の近くのリージョンを選ぶと、遅延（7章）が小さくなる
- 1つのリージョンの中は、電気・冷やす機械・回線が別々の、いくつかの**アベイラビリティゾーン**（AZ、ゾーン）に分かれている。サーバーを2つの AZ に分けて置けば、片方の建物が止まってもサービスは続く
- 個人情報などは、法律や会社の決まりで、国内のリージョンに置くことがある

この教科書の記録を合わせるしくみ（Firebase の Firestore）も、Google Cloud の東京（`asia-northeast1`）に置いています。

## データセンターの姿

![Google のデータセンター（アメリカ・アイオワ州）](images/google-dc.jpg)

クラウドの中身は、何万台ものサーバーが並ぶ、大きな建物です。

![データセンターが集まるバージニア州アッシュバーン](images/ashburn.jpg)

アメリカのバージニア州北部は、世界でいちばんデータセンターが集まっている所です。AWS の一番古いリージョン（`us-east-1`）もここにあります。日本では千葉県の印西市などに集まっています。

![データセンターの屋上の冷やす機械](images/dc-cooling.jpg)

- サーバーは電気を熱に変えるので、冷やすのに大きな電気がいる。外の冷たい空気や水を使って、冷やす電気を減らす工夫をしている。北海道の石狩など、寒い土地にもデータセンターが作られている
- 国際エネルギー機関（IEA）によると、データセンターは2024年に世界の電気の約1.5%を使い、AI のために2030年には約2倍になる見こみ

## 料金のしくみ

- **使った分だけ**: サーバーは動かした時間（秒・時間）、ディスクは置いた量（GB × 月）、データベースは読み書きの回数など
- **出ていくデータにお金がかかる**: インターネットからクラウドに入るデータはふつう無料、クラウドから外へ出すデータ（**エグレス**）は GB ごとにお金がかかる
- **無料の枠**: 小さなサーバーやデータベースなら、決まった量まで無料のものが多い
- **止め忘れに注意**: 試しに作ったサーバーを消し忘れると、毎月お金がかかる。最初に**予算のアラート**（使った金額が決めた額をこえたらメール）を設定しておく

## 責任の分け方

クラウドの会社は、建物・機械・仮想化のしくみを守ります。その上に置く OS の更新・パスワード・ファイアウォールの設定・データの公開範囲は、借りた人の責任です（**責任共有モデル**）。クラウドの事故の多くは、設定のまちがい（データの置き場所をだれでも見られる設定にした、など）で起きています。

## クラウドも止まる

2025年10月20日、AWS の `us-east-1` で、データベース（DynamoDB）の名前を DNS で引けなくなる障害が起き、世界中のたくさんのアプリやサイトが何時間も使えなくなりました。DNS（3章）の小さなまちがいが、大きく広がった例です。大事なサービスは、AZ やリージョンを分けて置き、止まったときにどうするかを決めておきます。

## まとめ

- クラウドは、データセンターのコンピューターを、インターネット越しに使った分だけ借りるしくみ
- IaaS（サーバー）・PaaS（アプリの置き場）・サーバーレス・SaaS（完成したアプリ）の順に楽になる
- AWS・Azure・Google Cloud が大きい。リージョン（東京・大阪）と AZ を選んで置く
- 料金は使った分だけ。外へ出すデータと止め忘れに注意し、予算のアラートを付ける
- 設定と中身は借りた人の責任。クラウドも止まることがある

## 練習問題

```quiz
Q: サーバーを自分で買って、自分の所に置いて使うことを何といいますか。
A: オンプレミス | オンプレ | on-premises | on-prem
E: クラウドは、使った分だけ借ります。

Q: 仮想のサーバーやディスクを借りて、OS から上を自分で用意する形を何といいますか（アルファベット4文字）。
A: IaaS | イアース
E: Amazon EC2 や Google Compute Engine が IaaS です。

Q: Gmail や Microsoft 365 のように、できあがったアプリを使う形を何といいますか（アルファベット4文字）。
A: SaaS | サース
E: 自分はアプリを使うだけです。

Q: 1つのリージョンの中にある、電気や回線が別々のデータセンターのまとまりを何といいますか。
A: アベイラビリティゾーン | AZ | ゾーン | availability zone
E: 2つの AZ に分けて置くと、片方が止まってもサービスを続けられます。

Q: クラウドから外へ出すデータの転送を何といいますか（GB ごとにお金がかかることが多い）。
A: エグレス | egress | データ転送 | アウトバウンド
E: クラウドに入れるデータ（イングレス）はふつう無料です。
```
