# 4. TCP と UDP（ポートと、確実に届けるしくみ）

IP アドレス（5章）は「どのコンピューターか」までしか決めません。1台の中では、ブラウザ・メール・SSH など、たくさんのアプリが同時に通信しています。どのアプリに渡すかを決め、必要なら「確実に・順番どおりに」届けるのが、トランスポート層の **TCP** と **UDP** です。

## ポート番号: どのアプリか

**ポート番号**は、1台の中のアプリを区別する 0〜65535 の番号です。IP アドレスが建物の住所なら、ポート番号は部屋番号です。

サーバーのアプリは、決まった番号で待っています（**ウェルノウンポート**、0〜1023）。

| ポート | プロトコル | 使い道 |
| --- | --- | --- |
| 22 | SSH | ほかのコンピューターに入って操作する（9章） |
| 53 | DNS | 名前を調べる（3章） |
| 80 | HTTP | Web |
| 443 | HTTPS（HTTP/3 は UDP の 443） | 暗号にした Web |
| 25・587 | SMTP | メールを送る |
| 123 | NTP | 時計を合わせる |
| 1883・8883 | MQTT（8883 は暗号つき） | IoT の機械とサーバー（12章） |
| 5000・8000・8080 | （決まりはない） | 開発中の Web サーバーでよく使う |

つなぎに行く側（ブラウザなど）は、OS がそのつど空いている番号を選びます（**エフェメラルポート**。Linux では 32768〜60999）。

1本の通信は、「送る側の IP アドレスとポート・受ける側の IP アドレスとポート・TCP か UDP か」の5つの組で区別されます。だから、同じサーバーの 443番に、同じパソコンから何本つないでも混ざりません。

```bash
ss -tn       # いまつながっている TCP（t）を、名前に変えずに数字で（n）
```

```text
State   Recv-Q  Send-Q  Local Address:Port    Peer Address:Port
ESTAB   0       0       192.168.3.123:33416   104.20.23.154:443
ESTAB   0       0       192.168.3.123:40048   185.199.108.153:443
```

左が自分（エフェメラルポート）、右が相手（443 = HTTPS）です。

## TCP: 確実に、順番どおりに届ける

**TCP**（Transmission Control Protocol）は、なくなったり順番が入れかわったりするかもしれない IP の上で、「全部・順番どおりに・こわれずに」届けるしくみです。Web・メール・SSH・ファイルの転送など、1バイトも欠けては困るものに使います。

### 3ウェイハンドシェイク: つなぐ前のあいさつ

![TCP のやりとり（つなぐ・送る・切る）](images/tcp.svg)

TCP は、データを送る前に3回のあいさつで**コネクション**（つながり）を作ります。

1. **SYN**: 「つなぎたいです。私の番号は 1000 から始めます」
2. **SYN + ACK**: 「いいですよ。1000 は受け取りました。私の番号は 5000 から始めます」
3. **ACK**: 「5000 も受け取りました」

これで、おたがいが送り・受け取れることがわかります。相手が遠いと、このあいさつだけで行って帰る時間（**RTT**）が1回分かかります。

### 番号と ACK で、なくなったら送り直す

- データの1バイトずつに**シーケンス番号**を付けて送る。受け取る側は番号順に並べ直す
- 受け取ったら「ここまで受け取った」と **ACK**（確認応答）を返す
- しばらく ACK が来なければ、なくなったとみなして**再送**する
- 受け取る側が「あとこれだけ受け取れる」（**ウィンドウ**）を伝え、送る側は ACK を待たずにそこまでまとめて送る（**フロー制御**）
- ネットワークが混んでいる様子（なくなったパケットや遅れ）を見て、送る速さを自分で落とす（**輻輳制御**）。みんなが送りすぎて全員が遅くなるのを防ぐ

終わるときは、両方が **FIN** を送り合って切ります。

## UDP: 送りっぱなしで、速く軽く

**UDP**（User Datagram Protocol）は、あいさつも ACK も再送もありません。ポート番号を付けて送るだけです。

- つなぐ準備がいらないので、すぐ送れる
- なくなっても送り直さない。送り直したデータが遅れて届いても意味がないものに向く
- アプリが自分で、なくなったときの対応を決める

| | TCP | UDP |
| --- | --- | --- |
| つなぐ準備 | 3ウェイハンドシェイク | なし |
| なくなったら | 送り直す | 送り直さない |
| 順番 | そろえる | そろえない |
| 速さ・軽さ | 少し重い | 軽い |
| 使い道 | Web・メール・SSH・ファイル | DNS・ビデオ通話・オンラインゲーム・生放送・時計合わせ（NTP） |

ビデオ通話で、1秒前の映像を送り直してもらっても意味がありません。少し乱れても、いまの映像を流し続けるほうが大事です。

### QUIC: UDP の上で、TCP のようなことをする

HTTP/3 の **QUIC**（2章）は、UDP の上で、再送や順番のそろえ方を自分で行います。TCP と暗号（TLS、9章）のあいさつを1回にまとめて速くし、スマホの回線が切り替わってもつながりを続けられます。

## 試してみる: `nc` で TCP と UDP

`nc`（netcat）を使うと、TCP や UDP で文字を送れます。同じパソコンで、ターミナルを2つ開いて試します（ラズパイと PC の間でもできます。そのときは `localhost` を相手の IP アドレスに）。

```bash
# ターミナル1: TCP の 5000番で待つ
nc -l 5000

# ターミナル2: つないで送る（-N は送り終わったら切る）
echo "hello from pc" | nc -N localhost 5000
```

ターミナル1に `hello from pc` と出ます。UDP なら `-u` を付けます。

```bash
nc -u -l 5001                              # ターミナル1
echo "temp=21.5" | nc -u -w0 localhost 5001   # ターミナル2
```

相手のポートが開いているかだけを確かめるには `-z` を使います（13章）。

```bash
nc -zv example.com 443
```

```text
Connection to example.com (172.66.147.243) 443 port [tcp/https] succeeded!
```

## まとめ

- ポート番号で、1台の中のどのアプリかを決める。サーバーは決まった番号（22・53・80・443 など）で待つ
- TCP は、3ウェイハンドシェイクでつなぎ、番号と ACK と再送で、全部・順番どおりに届ける
- UDP は送りっぱなしで軽い。DNS・通話・ゲームなどに使う
- QUIC（HTTP/3）は UDP の上で TCP のようなことをする

## 練習問題

```quiz
Q: SSH がふつう使うポート番号は何番ですか。
A: 22
E: HTTP は 80、HTTPS は 443、DNS は 53 です。

Q: TCP がつなぐときの3回のあいさつで、最初に送るものは何ですか。
A: SYN | シン
E: SYN → SYN + ACK → ACK の順です。

Q: 受け取ったことを相手に知らせるために返すものを何といいますか（アルファベット3文字）。
A: ACK | 確認応答 | acknowledgement
E: しばらく ACK が来なければ、送る側は再送します。

Q: 再送をせず、送りっぱなしにするトランスポート層のプロトコルは何ですか。
A: UDP
E: DNS やビデオ通話・オンラインゲームで使います。

Q: TCP で、ネットワークの混み具合を見て、送る速さを自分で落とすしくみを何といいますか。
A: 輻輳制御 | ふくそう制御 | congestion control
E: 受け取る側の余裕に合わせるのはフロー制御です。
```
