# 14. Adding a machine learning model

## What you will learn

- How to think about running machine learning on a microcontroller (TinyML)
- Making "features" from sensor data
- Collecting data and training on the PC
- Converting the trained decision tree into C++ code that runs on the Pico (`model.h`) and classifying with it
- Options when you want to use larger models

This assumes you have done Chapters 8–9 (wiring and reading the MPU-6050) and Chapter 13 (sending data to the PC).

## The overall flow

![The flow of running machine learning on a microcontroller](images/en/ml-flow.svg)

1. **Collect**: take sensor data on the Pico, attach the name of the behavior (a label) and save it
2. **Train**: make a model on the PC with scikit-learn
3. **Convert**: turn the trained model into code that runs on the Pico
4. **Infer**: run the model on the Pico and classify on the spot

The basic idea is **training on the PC, and only inference (classification) on the microcontroller**.
The Pico has only about 200 KB of RAM, so it cannot do the training itself, but it is plenty for classifying with a small model.

### Terms

| Term | Meaning |
| --- | --- |
| Label | The "correct name" attached to data. For example rest, walk, eat |
| Feature | A number that summarizes a characteristic of the raw data. For example the mean or spread over 2 seconds |
| Window | The unit the data is cut into. 2 seconds in this chapter |
| Training | Making classification rules from pairs of data and labels |
| Inference | Guessing the label of new data with the rules you made |
| Model | The classification rules made by training |

## Use "features", not raw data

Measuring acceleration at 25 Hz for 2 seconds gives 3 axes × 50 times = 150 numbers.
Rather than putting these straight into a model, summarizing them into **a few numbers that capture the characteristics well (features)** makes a smaller, more accurate model.

![From raw data to features to classification](images/en/windows-features.svg)

| Feature | What it tells you |
| --- | --- |
| Mean of each axis | Which way the neck is pointing (head up or down) |
| Standard deviation of each axis | How big the movement is in each direction |
| Standard deviation of the acceleration magnitude | How vigorous the overall movement is (large for walking, small for resting) |
| Mean change in the acceleration magnitude | Small, fast movements (chewing, rumination) |

In this example, the following **8** features are made every 2 seconds.
`mean_x, mean_y, mean_z, std_x, std_y, std_z, std_mag, diff_mag`

> **Standard deviation** is "how spread out the values are". It is small when still and large when moving vigorously.

## Step 1: Collect data (Pico)

C++ has no file system, so the features are **printed in CSV form with `printf`** and received on the PC.
Set `LABEL` to the name of a behavior, flash it, and collect data while doing that behavior.

```cpp run
#include <cmath>
#include <cstdio>
#include "pico/stdlib.h"
#include "mpu6050.h"

const char* LABEL = "rest";           // <- the behavior name. Flash several times, changing it to walk / eat / rest and so on
constexpr int WINDOWS = 30;           // 2 s x 30 = collect for 1 minute
constexpr int HZ = 25;
constexpr int N = HZ * 2;             // samples in one window

Mpu6050 mpu(i2c0);
float xs[N], ys[N], zs[N];

// collect 2 seconds' worth at fixed intervals
void window() {
    absolute_time_t next = get_absolute_time();
    for (int i = 0; i < N; i++) {
        mpu.read_accel(xs[i], ys[i], zs[i]);
        next = delayed_by_ms(next, 1000 / HZ);
        sleep_until(next);
    }
}

float mean(const float* a) {
    float s = 0;
    for (int i = 0; i < N; i++) s += a[i];
    return s / N;
}

float stdev(const float* a, float m) {
    float s = 0;
    for (int i = 0; i < N; i++) s += (a[i] - m) * (a[i] - m);
    return sqrtf(s / N);
}

// make the 8 features. Classification (step 3) must always use exactly the same calculation
void features(float fe[8]) {
    float mag[N];
    for (int i = 0; i < N; i++) mag[i] = sqrtf(xs[i] * xs[i] + ys[i] * ys[i] + zs[i] * zs[i]);
    float mx = mean(xs), my = mean(ys), mz = mean(zs), mm = mean(mag);
    float diff = 0;
    for (int i = 1; i < N; i++) diff += fabsf(mag[i] - mag[i - 1]);
    fe[0] = mx;  fe[1] = my;  fe[2] = mz;
    fe[3] = stdev(xs, mx);  fe[4] = stdev(ys, my);  fe[5] = stdev(zs, mz);
    fe[6] = stdev(mag, mm);
    fe[7] = diff / (N - 1);
}

int main() {
    stdio_init_all();
    mpu.begin(4, 5);
    sleep_ms(3000);                   // time to get ready between flashing and starting the movement

    for (int w = 0; w < WINDOWS; w++) {
        window();
        float fe[8];
        features(fe);
        for (int i = 0; i < 8; i++) printf("%.4f,", fe[i]);
        printf("%s\n", LABEL);
    }
    printf("done\n");
    while (true) sleep_ms(1000);
}
```

Every 2 seconds, one line appears in the output box.

```text
0.0123,-0.0201,0.9987,0.0031,0.0029,0.0035,0.0024,0.0021,rest
0.0119,-0.0198,0.9991,0.0028,0.0031,0.0033,0.0022,0.0019,rest
```

- `float mag[N];` is an array inside a function, but with 50 elements (200 bytes) it is small enough. Put large arrays outside functions (Chapter 13)
- `sqrtf` and `fabsf` are the `float` versions of the functions (`sqrt` without `f` is for `double` and slow)

### How to practice (you can try it without a cow)

Hold the sensor in your hand and collect data by imitating the movements yourself.

| LABEL | What to do |
| --- | --- |
| `rest` | Put the sensor on the desk and do not move it |
| `walk` | Hold the sensor and walk slowly (or move your hand up and down widely) |
| `eat` | Move the hand holding the sensor left and right, small and fast |

1. Set `LABEL = "rest"`, flash, and start watching the output in Serial Monitor. Wait for 1 minute without moving it
2. Change it to `LABEL = "walk"` and flash again. Make walking movements for 1 minute
3. Change it to `LABEL = "eat"` and flash again. Make small, fast movements for 1 minute
4. Select and copy the lines of numbers from Serial Monitor and keep pasting them into `features.csv` in a text editor (leave out lines like `done`)

> **With real cow data**: it is common to record with the sensor on a collar while filming video at the same time, then watch the video later and label things like "these 2 seconds were eating".
> Collecting at least tens to hundreds of windows per behavior makes it stable.

> Instead of copying, you can also receive and save with a PC-side program like `pc_logger.py` in Chapter 13. In that case, change it to save only lines where `line.count(",") == 8`.

## Step 2: Train on the PC

From here on, run things **on the PC**. scikit-learn is needed.

```bash
sudo apt install python3-sklearn
```

A decision tree is a model that classifies with **a combination of if statements**, such as "if std_mag is 0.05 or less, then...".
It is light to compute and converts directly into if statements, so it is very well suited to microcontrollers.

![An illustration of a decision tree](images/en/decision-tree.svg)

```python
# train.py  - usage: python3 train.py
import csv
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split
from sklearn.metrics import classification_report

NAMES = ["mean_x", "mean_y", "mean_z", "std_x", "std_y", "std_z", "std_mag", "diff_mag"]

X, y = [], []
with open("features.csv") as f:
    for row in csv.reader(f):
        if len(row) == 9:
            X.append([float(v) for v in row[:8]])
            y.append(row[8])

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=0, stratify=y)

clf = DecisionTreeClassifier(max_depth=4, random_state=0)   # limit the depth to keep it small
clf.fit(X_train, y_train)
print(classification_report(y_test, clf.predict(X_test)))

def export(clf, names):
    """convert the decision tree into MicroPython if statements"""
    t = clf.tree_
    lines = ["# decision tree generated by train.py", "def predict(f):"]

    def walk(node, depth):
        pad = "    " * depth
        if t.feature[node] >= 0:                      # a branch node
            i = t.feature[node]
            lines.append(f"{pad}if f[{i}] <= {t.threshold[node]:.6f}:  # {names[i]}")
            walk(t.children_left[node], depth + 1)
            lines.append(f"{pad}else:")
            walk(t.children_right[node], depth + 1)
        else:                                         # a leaf (the result)
            label = clf.classes_[t.value[node][0].argmax()]
            lines.append(f"{pad}return {str(label)!r}")

    walk(0, 1)
    return "\n".join(lines) + "\n"

with open("model.py", "w") as f:
    f.write(export(clf, NAMES))
print("made model.py")

def export_cpp(clf, names):
    """convert the decision tree into C++ if statements"""
    t = clf.tree_
    lines = ["// decision tree generated by train.py", "#pragma once", "",
             "inline const char* predict(const float* f) {"]

    def walk(node, depth):
        pad = "    " * depth
        if t.feature[node] >= 0:
            i = t.feature[node]
            lines.append(f"{pad}if (f[{i}] <= {t.threshold[node]:.6f}f) {{  // {names[i]}")
            walk(t.children_left[node], depth + 1)
            lines.append(f"{pad}}} else {{")
            walk(t.children_right[node], depth + 1)
            lines.append(f"{pad}}}")
        else:
            label = clf.classes_[t.value[node][0].argmax()]
            lines.append(f'{pad}return "{label}";')

    walk(0, 1)
    lines.append("}")
    return "\n".join(lines) + "\n"

with open("model.h", "w") as f:
    f.write(export_cpp(clf, NAMES))
print("made model.h (for C++)")
```

> Click a function or argument name in the code (`train_test_split`, `stratify`, `max_depth` and others) to see its meaning (Chapter 0).

### Steps

1. Copy the code above with the "Copy" button and save it as `train.py` in the same folder as `features.csv`
2. In the terminal, move to that folder and type `python3 train.py`
3. A score table is shown, and `model.h` (for C++) and `model.py` (for MicroPython, to try in Appendix E) are created in the same folder

### Reading the score table

```text
              precision    recall  f1-score   support

         eat       0.89      0.89      0.89         9
        rest       1.00      1.00      1.00         9
        walk       0.89      0.89      0.89         9

    accuracy                           0.93        27
```

| Item | Meaning |
| --- | --- |
| precision | Of those classified as "eat", the share that really were eat |
| recall | Of the real eat cases, the share correctly classified as eat |
| f1-score | The balance of precision and recall. 1.00 is perfect |
| support | The number of test data items |
| accuracy | The overall share correct |

- The scores are measured on data not used for training (30% of the total)
- If accuracy is low, add more data, add more features or change `max_depth`

The resulting `model.py` looks something like this.

```python
def predict(f):
    if f[6] <= 0.031200:  # std_mag
        return 'rest'
    else:
        if f[7] <= 0.084500:  # diff_mag
            return 'eat'
        else:
            return 'walk'
```

It is the decision tree in the figure above, turned directly into if statements. `f[6]` is the 7th of the 8 features (std_mag) (counting from 0).

## Step 3: Classify on the Pico

`model.h` has a form like this (the contents change with the data you trained on).

```text
// decision tree generated by train.py
#pragma once

inline const char* predict(const float* f) {
    if (f[6] <= 0.041200f) {  // std_mag
        return "rest";
    } else {
        if (f[7] <= 0.183000f) {  // diff_mag
            return "walk";
        } else {
            return "eat";
        }
    }
}
```

1. Copy the `model.h` made on the PC into your VS Code project folder (for example `cp model.h ~/apps/collar/`)
2. Copy `mpu6050.h` too (Chapter 9). Add `hardware_i2c` to `CMakeLists.txt`
3. Paste the following program into the `.cpp`, then Compile → Run

```cpp run
#include <cmath>
#include <cstdio>
#include "pico/stdlib.h"
#include "mpu6050.h"
#include "model.h"                    // the model.h made by train.py

constexpr int HZ = 25;
constexpr int N = HZ * 2;

Mpu6050 mpu(i2c0);
float xs[N], ys[N], zs[N];

void window() {
    absolute_time_t next = get_absolute_time();
    for (int i = 0; i < N; i++) {
        mpu.read_accel(xs[i], ys[i], zs[i]);
        next = delayed_by_ms(next, 1000 / HZ);
        sleep_until(next);
    }
}

float mean(const float* a) {
    float s = 0;
    for (int i = 0; i < N; i++) s += a[i];
    return s / N;
}

float stdev(const float* a, float m) {
    float s = 0;
    for (int i = 0; i < N; i++) s += (a[i] - m) * (a[i] - m);
    return sqrtf(s / N);
}

// the same calculation as step 1
void features(float fe[8]) {
    float mag[N];
    for (int i = 0; i < N; i++) mag[i] = sqrtf(xs[i] * xs[i] + ys[i] * ys[i] + zs[i] * zs[i]);
    float mx = mean(xs), my = mean(ys), mz = mean(zs), mm = mean(mag);
    float diff = 0;
    for (int i = 1; i < N; i++) diff += fabsf(mag[i] - mag[i - 1]);
    fe[0] = mx;  fe[1] = my;  fe[2] = mz;
    fe[3] = stdev(xs, mx);  fe[4] = stdev(ys, my);  fe[5] = stdev(zs, mz);
    fe[6] = stdev(mag, mm);
    fe[7] = diff / (N - 1);
}

int main() {
    stdio_init_all();
    mpu.begin(4, 5);

    while (true) {
        window();
        float fe[8];
        features(fe);
        uint64_t t0 = time_us_64();
        const char* label = predict(fe);
        unsigned us = static_cast<unsigned>(time_us_64() - t0);
        printf("result: %s  (classification took %u us)\n", label, us);
    }
}
```

Every 2 seconds, a result appears like this (the times are examples). Move the sensor and check that the result changes.

```text
result: rest  (classification took 2 us)
result: walk  (classification took 2 us)
```

> `features()`, which makes the features, must **always be exactly the same calculation as when collecting**.
> If it differs even a little, you will not get the accuracy measured on the PC.

> If you see `fatal error: model.h: No such file or directory`, `model.h` is not in the project folder (the same place as the `.cpp`).

Classification with a decision tree takes a few microseconds. Even including the feature calculation, it is a tiny fraction of the 2 seconds.

## When you want larger models

| Method | Good for | Language |
| --- | --- | --- |
| Converting a decision tree into if statements (this chapter) | Simple classification with few features | C++ (MicroPython too) |
| [emlearn](https://github.com/emlearn/emlearn) | scikit-learn models such as random forests and small neural networks | C (there is also a [MicroPython version](https://github.com/emlearn/emlearn-micropython)) |
| [LiteRT for Microcontrollers](https://ai.google.dev/edge/litert/microcontrollers/overview) / [pico-tflmicro](https://github.com/raspberrypi/pico-tflmicro) | Neural networks made with TensorFlow / Keras (using audio or raw data directly) | C++ |
| [Edge Impulse](https://edgeimpulse.com/) | When you want to do data collection, labeling, training and export all together in the browser | Exports to C++ |

**A rough guide to choosing**

- Try a decision tree first. It is enough to check whether the behaviors can be separated to some degree
- If accuracy is not enough, a random forest (emlearn)
- If you want to learn directly from raw waveforms, or use sound too, a neural network (LiteRT / Edge Impulse, C++)

### Tips for making models smaller

- Keep a decision tree's `max_depth` at around 4–8
- **int8 quantization** of a neural network makes it about 1/4 the size and faster
- Reduce the number of features (`clf.feature_importances_` shows which ones are not helping)

## Summary

- Train on the PC; only classify on the Pico
- Summarize raw data into features every 2 seconds before putting it into the model
- A decision tree can be converted into if statements, and runs in C++ as is by `#include`-ing `model.h`
- For larger models, use emlearn, LiteRT or Edge Impulse (C/C++)
