# 1. Docker とは

## 「自分のパソコンでは動くのに」をなくす

プログラムは、OS・Python のバージョン・ライブラリなどの**環境**がそろって、はじめて動きます。

- 自分のパソコンでは動くのに、ラズパイやほかの人のパソコンでは動かない
- プロジェクト A は Python 3.10、プロジェクト B は 3.12 がほしい
- データベースを試したいが、パソコンに直接入れて設定を汚したくない

**Docker** は、プログラムと、それが動く環境をまとめて箱（**コンテナ**）に入れ、どこでも同じように動かす道具です。

## 仮想マシンとのちがい

![仮想マシンとコンテナ](images/vm.svg)

| | 仮想マシン（VirtualBox など） | コンテナ（Docker） |
| --- | --- | --- |
| 中身 | OS をまるごと1つ動かす | アプリとライブラリだけ。OS（Linux のカーネル）はホストと共有 |
| 大きさ | 数 GB | 数十〜数百 MB |
| 起動 | 数十秒〜数分 | 1 秒くらい |
| いくつも動かす | 重い | 軽い |

コンテナは Linux の仕組みで動きます。Windows や Mac では、Docker Desktop が中で小さな Linux を動かしています。Ubuntu・ラズパイ・Jetson なら、そのまま動きます。

## イメージ・コンテナ・Dockerfile

![Dockerfile からコンテナまで](images/flow.svg)

| 言葉 | 意味 | たとえ |
| --- | --- | --- |
| **Dockerfile** | イメージの作り方を書いたテキスト | 料理のレシピ |
| **イメージ** | コンテナのひな形。OS の一部・ライブラリ・アプリが入っている。中身は変わらない | 冷凍食品 |
| **コンテナ** | イメージから作って、動かしている実体。1つのイメージからいくつでも作れる | 温めて皿に出したもの |
| **Docker Hub** | イメージを置いておく場所（レジストリ）。Python・Ubuntu・データベースなどの公式イメージがある | お店 |

- `docker pull` で Docker Hub からイメージをもらい、`docker run` でコンテナを作って動かす（3章）
- 自分のアプリのイメージは、Dockerfile を書いて `docker build` で作る（4章）

## Docker でできること

| 使い道 | 例 |
| --- | --- |
| 試す | パソコンを汚さずに、データベースや新しい版の Python を試して、すぐ消す |
| 開発の環境をそろえる | VS Code の Dev Containers で、プロジェクトごとの環境の中で開発する（7章） |
| 何個かのものを組み合わせる | Web アプリ＋データベース を1つのファイルでまとめて動かす（6章） |
| 配る・置く | 作ったアプリをイメージにして、ラズパイ・Jetson・サーバーで同じように動かす（8章） |

## まとめ

- コンテナは、アプリと環境を入れた軽い箱。OS はホストの Linux を共有する
- Dockerfile（レシピ）→ `docker build` → イメージ（ひな形）→ `docker run` → コンテナ（実体）
- イメージは Docker Hub からもらえる

## 練習問題

```quiz
Q: コンテナのもとになる、ひな形を何といいますか。
A: イメージ | image | Docker イメージ
E: Dockerfile（レシピ）→ `docker build` → イメージ → `docker run` → コンテナです。

Q: イメージを作るためのレシピになるファイルの名前は何ですか。
A: Dockerfile
E: `docker build` で、Dockerfile からイメージを作ります。

Q: いろいろなイメージをもらえる、Docker の公式の置き場は何ですか。
A: Docker Hub | DockerHub
E: `python` や `nginx` などのイメージがあります。

Q: コンテナが仮想マシンより軽いのは、何をホストと共有しているからですか。
A: OS | Linux | カーネル | Linux カーネル
E: コンテナはホストの Linux（カーネル）を共有します。仮想マシンは OS ごと持ちます。
```
